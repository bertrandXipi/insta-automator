### 3.4 Fix critique nginx (vraie cause du "rien ne change en prod")

`nginx.conf` ne posait **aucun** `Cache-Control` sur `index.html`, donc les navigateurs appliquaient leur heuristique de cache et continuaient à pointer sur l'ancien bundle JS — qui lui était `immutable` 1 an (normal pour les assets hashés Vite).

Diff appliqué :

```nginx
# Ajouté
location = /index.html {
    add_header Cache-Control "no-store, no-cache, must-revalidate, max-age=0";
    try_files $uri =404;
}

location / {
    try_files $uri $uri/ /index.html;
    add_header Cache-Control "no-store, no-cache, must-revalidate, max-age=0";
}

# Inchangé
location ~* \.(js|css|png|jpg|jpeg|gif|ico|svg|woff|woff2)$ {
    expires 1y;
    add_header Cache-Control "public, immutable";
}
```

Vérifié avec `curl -sI` : `cache-control: no-store, no-cache, must-revalidate, max-age=0` est bien présent sur `/`.

> **Conséquence pour le client / utilisateurs déjà en cache** : il faut UNE seule fois faire `Cmd+Shift+R` (Mac) ou `Ctrl+Shift+R` (Win/Linux) sur l'URL prod. Après ça, tous les futurs déploiements seront visibles automatiquement.
